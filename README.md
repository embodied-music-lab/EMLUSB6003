# EMLUSB6003

EMLUSB6003 is a driver for the National Instruments USB-6003 data acquisition card and its OEM version. It streams the card's analog inputs as raw counts and volts.

Created by Ian Howell. Code generated by Claude (Anthropic). Questions and error reports: office@embodiedmusiclab.com. No support is implied.

Not affiliated with or endorsed by National Instruments. USB-6003 and NI are names of National Instruments products; they are used here only to identify the hardware this code talks to.

## Choose an implementation

The repository holds two implementations of the same driver. Each works on its own; neither needs the other.

- **Python** runs as an ordinary program on Windows, macOS and Linux. It reaches the card through pyusb and the libusb library. It doesn't use a web browser.
- **JavaScript** runs inside a web page in Chrome or another Chromium-based browser, such as Microsoft Edge, on Windows, macOS, Linux and ChromeOS. It reaches the card through the browser's WebUSB interface, which Chromium ships on all four systems ([Intent to Ship: WebUSB](https://groups.google.com/a/chromium.org/d/msg/blink-dev/KuXx_k2KIis/-g-75FScBgAJ)). Safari and Firefox don't support WebUSB ([MDN: USB](https://developer.mozilla.org/en-US/docs/Web/API/USB)).

On a Chromebook, use the JavaScript implementation.

Whichever implementation you choose, set up your operating system first. See [Set up your operating system](#set-up-your-operating-system).

## Supported cards

| Card | USB vendor ID | USB product ID |
|---|---|---|
| NI USB-6003 | `0x3923` | `0x76C6` |
| NI USB-6003, OEM version | `0x3923` | `0x76C7` |

Both IDs are in the `PRODUCTS` table in `python/emlusb6003/protocol.py` and `js/src/protocol.js`.

## Install

### Python

You need Python 3.8 or later, pyusb and libusb 1.0. pyusb has built-in backends for libusb and works best with libusb 1.0 ([pyusb tutorial](https://github.com/pyusb/pyusb/blob/master/docs/tutorial.rst)).

```
brew install libusb                  # macOS
sudo apt install libusb-1.0-0        # Debian and Ubuntu
python3 -m pip install ./python      # from a clone of this repository
```

On Windows, see [Windows](#windows) first. To run the tests, also install pytest.

### JavaScript

You need Chrome or another Chromium-based browser. There's nothing else to install. WebUSB works only on a secure origin: `https://` or `http://localhost`. To try the example page, serve the `js` folder:

```
cd js
python3 -m http.server 8000
```

Then open `http://localhost:8000/examples/`. The browser asks you to pick the card. The page also has a simulated card that needs no hardware.

## Quick start

### Python

```python
from emlusb6003 import Usb6003

with Usb6003.open_device() as card:
    rate = card.configure([0, 1, 2], 1000)    # ai0, ai1, ai2, 1000 frames per second each
    print(f"true rate: {rate} frames per second for each input")
    card.start()
    for _ in range(10):
        frames = card.read()                  # None if nothing arrived within a second
        if frames:
            print(frames.first_frame, frames.counts[:3], frames.volts[:3])
    card.stop()
```

The example `python/examples/stream_to_csv.py` streams to a CSV file. Run it with `--simulate` to try it with no hardware.

### JavaScript

```js
import { Usb6003 } from "./src/index.js";

button.onclick = async () => {                          // the chooser needs a click
  const card = await Usb6003.request();
  const rate = await card.configure([0, 1, 2], 1000);   // true rate for each entry
  await card.start();
  const frames = await card.read();                     // null if nothing arrived within a second
  console.log(frames.firstFrame, frames.counts, frames.volts);
  await card.stop();
  await card.close();
};
```

The example page `js/examples/index.html` lists, opens, configures and streams a card, and shows live numbers for each input.

## API

The two languages use the same names. Python uses snake_case and JavaScript uses camelCase. In JavaScript every call that talks to the card returns a promise.

| Call | What it does |
|---|---|
| `Usb6003.open_device(serial=None)` / `Usb6003.request()` | Finds the card and opens it. `request()` shows the browser's chooser. |
| `card.configure(inputs, rate_per_input)` | Sets the channel list and the rate for each entry. Returns the true rate per entry. Raises `ProtocolError` for a request outside the card's limits. |
| `card.start()` | Begins collecting frames in the background. |
| `card.read(timeout)` / `card.read({ timeout })` | Returns the frames that have arrived, or nothing after the timeout. The timeout is in seconds in Python (default 1) and in milliseconds in JavaScript (default 1000). |
| `card.stop()` | Stops the stream. Frames already received can still be read. |
| `card.close()` | Stops if needed and releases the card. |

`inputs` is a list of input numbers 0 to 7, for `ai0` to `ai7`. The list can be in any order and can repeat an input.

`rate_per_input` is the number of frames per second you want for each entry. The timebase allows only certain rates, so the true rate is at or just above the request. `configure()` returns the true rate.

`read()` returns whole frames. A frame holds one value for each list entry, in list order.

| Field | Meaning |
|---|---|
| `counts` | Raw signed 16-bit counts, frame after frame |
| `volts` | The same values in volts |
| `entries`, `inputs` | Values per frame, and the input number of each entry |
| `first_frame` / `firstFrame` | The number of the first frame since `start()` |
| `gap_s` / `gapS` | Normally empty. After a recovered halt, the seconds of data lost |
| `channel(entry, volts)`, `rows(volts)` | One entry's values, or frames one at a time |

A halt that can't be recovered ends the stream: the next `read()` after the frames that arrived before it raises `StreamLost`.

Pass `on_event` (Python) or `onEvent` (JavaScript) to receive `halted` and `recovered` events.

## Set up your operating system

### Windows

This step applies to both implementations. On Windows, the card must use Microsoft's WinUSB driver in place of the manufacturer's driver. libusb and WebUSB open a device only when WinUSB is bound to it ([Building a device for WebUSB](https://developer.chrome.com/docs/capabilities/build-for-webusb)). While WinUSB is bound, the manufacturer's software can't use the card.

One workable way to bind WinUSB uses Zadig, a free third-party program:

1. Download Zadig from the [libwdi releases page](https://github.com/pbatard/libwdi/releases).
2. Plug in the card and start Zadig.
3. In the **Options** menu, select **List All Devices**. The card already has a driver, so it doesn't appear otherwise ([Zadig wiki](https://github.com/pbatard/libwdi/wiki/Zadig)).
4. In the device list, pick the card. Check that the ID shows `3923` and `76C6` (or `76C7` for the OEM version).
5. In the driver box, select **WinUSB**.
6. Click **Replace Driver**.
7. Wait for Zadig to report success, then close it.

Changing the driver doesn't uninstall NI-DAQmx. To give the card back to the manufacturer's software:

1. Open **Device Manager** and find the card under **Universal Serial Bus devices**.
2. Right-click it and select **Uninstall device**. Select **Delete the driver software for this device** if Windows offers it.
3. Unplug the card, wait a few seconds, and plug it in again. If NI-DAQmx is installed, Windows picks the manufacturer's driver.

### macOS

Neither implementation needs a driver on macOS. For WebUSB, Chrome's guidance says nothing special is necessary on macOS, and a page can claim any interface that a kernel driver or another application hasn't claimed ([Building a device for WebUSB](https://developer.chrome.com/docs/capabilities/build-for-webusb)). If the manufacturer's software is running, quit it first, because only one program can hold the card at a time.

### Linux

This step applies to both implementations. By default most distributions don't give user accounts permission to open USB devices, and udev assigns that permission ([Building a device for WebUSB](https://developer.chrome.com/docs/capabilities/build-for-webusb)). Install the rule in `platform/99-usb6003.rules`:

```
sudo cp platform/99-usb6003.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
```

Then unplug and replug the card. The rule gives the `plugdev` group, and the person logged in at the machine, access to both product IDs.

### ChromeOS

Only the JavaScript implementation runs on ChromeOS. Open the example page in Chrome as described in [JavaScript](#javascript) under Install.

## Tests

The tests need no hardware and no browser.

```
python3 -m pip install pytest pyusb
python3 -m pytest                  # Python tests and the cross-language agreement test
cd js && node --test               # JavaScript tests, Node 18 or later
```

- `tests/test_cross_language.py` checks that the Python and JavaScript definitions agree.
- The simulated cards (`SimulatedCard`, `SimulatedUsbDevice`) send synthetic values.
